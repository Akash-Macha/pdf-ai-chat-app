pdf-ai-chat-app · quick visual guide

How your PDF becomes a chat partner.

The app does two different jobs: it builds a searchable memory once at upload time, then looks up that memory whenever someone asks a question.

Upload time = prepare the memoryQuestion time = retrieve evidence, then answer
Part 1 Upload time — build the searchable memory
📄
01 · PyPDF2

Extract text

Reads every PDF page and turns it into plain words.

✂️
02 · Text splitter

Make chunks

Creates 1,000-character notes with a 200-character overlap so ideas do not get cut off.

✦
03 · OpenAI embeddings

Map meaning

Turns every chunk into a vector: coordinates based on its meaning.

⌕
04 · FAISS

Build the index

Organizes vectors so similar meanings can be found extremely fast.

💾
05 · save_local

Save to disk

Stores the index in UPLOADED_PDF_FILE_INDEX for later.

Part 2 Question time — look up, then answer
💬
01 · User

Ask a question

“What is the refund period?” arrives at the /query endpoint.

📂
02 · load_local

Open saved memory

The app reloads the previously saved FAISS index. No need to re-read the PDF.

🔎
03 · similarity_search

Find evidence

FAISS brings back the 3 chunks whose meaning is closest to the question.

🤖
04 · LangChain + ChatOpenAI

Answer with context

Retrieved chunks + question go to the LLM, which writes the final answer.

Remember the RAG rule

Look it up, then answer. FAISS finds relevant PDF evidence; the LLM turns that evidence into a natural-language reply.

Who does what?

PyPDF2 reads. The splitter makes notes. Embeddings map meaning. FAISS retrieves. LangChain coordinates. The LLM answers.
